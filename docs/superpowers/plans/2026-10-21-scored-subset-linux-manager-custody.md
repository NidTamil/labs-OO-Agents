# Scored subset Linux manager custody implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task by task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Give exactly one budgeted subset preparation a manager-owned, independently timed Linux process boundary and immutable worker material through first use, with truthful crash recovery and exact owned cleanup.

**Architecture:** A durable one-use intent precedes a uniquely named transient systemd service whose small wrapper blocks on an unnamed socket until the controller has independently read back its identity, cgroup, limits and armed state. These tasks exercise a same-boot release with sealed material handles using an inert worker. Later guarded integration may perform staging inside the already armed cgroup only after the separate hard watchdog, fresh lease and other effect gates are proven. Recovery observes the same invocation and its retained cgroup rather than starting another service.

**Tech Stack:** Python 3.12, `uv`, pytest, systemd D-Bus on a version-proven disposable Linux host, cgroup v2, AF_UNIX descriptor passing and Linux file seals. No host installation or live control is part of writing or executing the offline slices of this plan.

**Spec:** [Scored native campaign](2026-10-11-scored-native-campaign.md), [primary takeover and run budget, Task 6E/6F](2026-10-21-primary-takeover-and-run-budget.md), and the [independent three-P1 process review](../../../reviews/process-supervisor-independent-review_2026-10-21.md). The existing one-preparation plan, bootstrap validator and release-prerequisite comparison are **inert claim checks**, not manager or material authorities.

## Primary interface basis and open choices

`StartTransientUnit(name, mode="fail", properties, aux)` creates/starts the service immediately; `mode="fail"` handles job conflict, not durable create-once semantics. `Type=exec` confirms that the **wrapper** was executed, not that the worker is released. In systemd v255, `StandardInputFileDescriptor` accepts a D-Bus FD, so the candidate passes one end of an unnamed `AF_UNIX` socketpair as wrapper stdin and retains the peer. The wrapper waits for one challenge-bound release message plus sealed FDs via `SCM_RIGHTS`; EOF, timeout, malformed or duplicate message denies release. On a separately proven v257+ manager, `ExtraFileDescriptors`/`ExtraFileDescriptorNames` is an optional direct-FD delivery design; it must not silently replace the v255 socketpair path. Version, property support and actual FD lifetime need disposable platform proof. [systemd D-Bus API](https://www.freedesktop.org/software/systemd/man/262/org.freedesktop.systemd1.html), [v255 transient stdin setter](https://raw.githubusercontent.com/systemd/systemd/v255/src/core/dbus-service.c), [v257 extra-FD setter](https://raw.githubusercontent.com/systemd/systemd/v257/src/core/dbus-service.c), [AF_UNIX descriptor passing](https://man7.org/linux/man-pages/man7/unix.7.html).

Require exact readback of unit name/job, boot ID, `InvocationID`, `ControlGroup` and, where supported, `ControlGroupId`, main PID, `Type=exec`, `ExitType=main`, `Restart=no`, `RemainAfterExit=no`, `KillMode=control-group`, `SendSIGKILL=yes`, finite `TimeoutStartSec`, `RuntimeMaxSec` and `TimeoutStopSec`, and no delegation/cgroup-write privilege. Pin the wrapper executable and its own loader/imports before service creation; keep that wrapper as the main process until its worker and owned cleanup end. `RuntimeMaxSec` counts held time but does not by itself prove a suspend-aware wall deadline; the separate hard-watchdog gate above remains open. The inert worker must remain in the manager cgroup through descendant creation. [systemd service lifecycle](https://www.freedesktop.org/software/systemd/man/255/systemd.service.html), [systemd kill modes](https://www.freedesktop.org/software/systemd/man/255/systemd.kill.html), [suspend-aware clock](https://man7.org/linux/man-pages/man2/clock_gettime.2.html), [PID 1 cgroup ownership](https://systemd.io/CONTROL_GROUP_INTERFACE/).

Immutable delivery is a measured design, not a blanket 64 MiB memfd rule: classify the exact one-preparation entrypoint, recursive Python imports, native libraries, package resources, task description/archive, templates, binaries, command and environment lookups. Static discovery is insufficient for dynamic import, `ctypes`/`dlopen`, resource and subprocess lookups. The real worker cannot release until an independently reviewed loader/namespace denies every undeclared lookup through first use. Sealed memfds and an FD-only loader are candidates for suitable bytes; larger or native dependencies need an independently verified immutable read-only image/mount or equivalent held-through-use mechanism. A hash followed by path reopening, `LoadCredential=PATH` or `OpenFile=PATH` alone cannot close the mutable-material P1. Unknown, ambient or mutable fallback fails closed. [memfd sealing](https://man7.org/linux/man-pages/man2/memfd_create.2.html).

For cleanup, retain an identity-checked FD to the exact cgroup v2 directory before the unit can be unloaded. At arm, join the FD's mount and inode identity (and cgroup ID where supported) to the manager's trusted `ControlGroup`/`ControlGroupId` readback; persist that join and recheck FD continuity at closure. An empty sibling FD never proves closure. Require the exact FD's `cgroup.events` **`populated=0`** (recursive) after exact-unit termination, not merely an inactive/missing unit, empty original session, absent PID or closed local transport. A coordinator crash may lose an ordinary FD: recovery requires independently retained, identity-verifiable FD custody or remains unresolved; reopening a matching pathname alone is not continuity proof. A missing/path-replaced cgroup FD leaves cleanup unresolved unless an independently authenticated reboot closes that exact boot's process question. Preserve a separately owned sentinel throughout every platform control. [Kernel cgroup v2 populated semantics](https://www.kernel.org/doc/html/latest/admin-guide/cgroup-v2.html).

## Review focus

1. An unrelated unreadable `/proc` entry or coordinator crash must not disable the manager's deadline; the worker must terminate by its own bounded unit/watchdog while the unrelated sentinel survives (Task 3/5).
2. A child that calls `setsid()` remains in the owned cgroup and is gone before cleanup is accepted (Task 5).
3. A verified source/archive/import path swapped after checking cannot change the bytes the released worker reads (Task 1/4).
4. A D-Bus reply lost after `StartTransientUnit` must never cause another start or release; read-only recovery must resolve the exact identity or stay blocked (Task 2/3/5).
5. Unit unload, cgroup path reuse, suspend/reboot, or failed intent/arm write cannot be turned into an empty-cgroup or fresh-deadline assertion (Task 2/4/5).
