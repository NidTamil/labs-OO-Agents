# Scored subset fresh-lease coordinator implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task by task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Serialize every schema-two budgeted-subset stop, fence and effect claim across the signed campaign ledger, resource store and UI mailbox, then make a fresh one-use lease possible without treating any independently committed store as an atomic cross-store transaction.

**Architecture:** A preparation-bound coordinator on the trusted POSIX SunChaser controller holds one protected cross-process guard while it records a durable intent, performs one exact store mutation or an ordered composite stop, and reads back each result. Its signed campaign state, resource store, controller UI mailbox and runtime signer remain on that controller. A crash leaves a pending intent that denies new effects until read-only reconciliation proves its outcome. Only after every schema-two writer adopts this protocol may a separate controller-side signer issue challenged, deadline-bound leases; the Windows workstation must authenticate and consume one immediately before its owned effect, within a locally measured residual deadline. The workstation's verifier-only `SubsetUiCustody` is a separate store outside the controller guard.

**Tech Stack:** Existing Python 3.12, SQLite, Xeus signed campaign events, `uv`, pytest and Ruff. Use fake guarded-store backends first; controller cross-process locking, held file descriptors/root identity, directory fsync and protected service/capability custody require disposable Linux proof. Windows Job/ACL/held-handle producer controls and Linux peer/ACK controls remain separate disposable platform gates.

**Spec:** [Primary takeover and run budget, Task 6F and fresh effect leases](2026-10-21-primary-takeover-and-run-budget.md), [scored campaign](2026-10-11-scored-native-campaign.md), and the [route-design decision package](../../../reviews/scored-subset-rpc-route-decision_2026-10-21.md). The read-only seam audit in the takeover plan found **no existing shared transaction or lock** spanning the signed Xeus state, resource-budget SQLite and UI-mailbox SQLite. This plan is source guidance, not a usable issuer or effect permit.

**Host placement evidence:** The [implementation-status ruling](2026-10-05-cybergym-implementation-status.md#L665) keeps Xeus authority, Docker/task runtime, attempt budget and oracle on POSIX SunChaser and the outbound one-shot UI client on Windows. ## Global constraints and writer map

- Scope only the explicit schema-two ten-task subset. Preserve schema-one mailbox, historical resource stores, full-cohort scheduler and existing task terminal meanings. No migration, automatic retry, second Send, or claim from a verifier-only RPC0 broker.
- The controller must independently verify exact run, epoch, admission/budget, preparation, attempt, signed state revision, resource-store identity and mailbox binding. A caller-supplied `next_action()`, snapshot, digest, clock or boolean is not permission.
- On the POSIX controller, protect the coordinator directory, lock file, journal, signed-state root, resource database, controller mailbox database and marker, and controller signing key against replacement or direct workstation writes; hold checked file descriptors and file/root/ancestor identities through use and prove directory-fsync durability. Ordinary UID ownership/mode checks cannot exclude another process running as the controller UID. The production design needs a separately protected service identity or equivalent OS-enforced capability boundary owning **all** these target stores and the signer while denying untrusted same-UID clients and the workstation direct writer access. The privileged controller manager remains trusted; this boundary does not claim to exclude it. Until disposable Linux proof of that boundary, schema-two effects remain disabled. A Python in-process lock, pathname check or SQLite transaction in only one of the three existing stores is insufficient. Test the chosen Linux cross-process lock, held file descriptors/root identity, directory fsync and service/capability custody on a disposable controller fixture before effect use. Keep Windows producer Job/ACL/held-handle proof separate; it cannot establish controller-store durability or custody.
- Use one lock order: coordinator guard, then resource transaction, signed-state append, mailbox transaction. Do not hold this guard across readiness waits, RPC, provider dispatch, UI effects or cleanup waits. Each guarded mutation has a bounded duration and exact durable intent before touching another store.
- The inert Task 1 fake-backed context does not prove a hard upper bound on a blocked writer body or stop priority while its guard is held. Task 2 production writer adoption remains blocked until independently timed owned-writer/guard expiry and stop-priority behavior are specified, implemented and proven on disposable Linux. A provisional journal operation count or byte cap may safely deny but must be calibrated above the maximum legitimate per-preparation attempt/control volume before integration; no unreviewed rotation or eviction may reuse identities.
- All schema-two writers must adopt the guard: `BudgetedSubsetState._append` and its preparation/start/terminal/quiescence/stop transitions; `RunResourceBudget` version-two creation, clock sampling, reservation, stop and closure; and `SubsetUiMailbox` create/open marker and SQLite initialization plus `publish`, `claim` and `acknowledge`, including cleanup fences and revocations. The inert Task 1 contract takes the alternative of requiring completed, independently proven mailbox marker and database initialization **before** coordinator binding; it must reject an `initialize` operation and keep effects disabled. Later Task 2 may introduce an exact two-object marker/DB initialization protocol only with separate ordered sub-intents and crash proof. Audit direct `CampaignAuthority.append_event` and raw SQLite write paths for bypass. Existing `budgeted_subset_runner._allow` followed by `mark_started` or `executor.start` is a check/use gap until converted. Workstation `SubsetUiCustody` is a separate remote store, so controller locking alone cannot authorize its effect.
- A stop or cleanup-fence **intent** blocks unfinished grants before its target-store write. Once a grant is activated, stop does not erase it: retain it as in-flight until authenticated settlement, local and remote closure and final accounting. An uncertain grant, lost reply or crash is never reissued under a new nonce. Owned cleanup remains possible after budget expiry, with truthful unresolved status if its proof is missing.
- Retain approved 15,000-request, 432,000-second including staging/cleanup and 500,000,000-USD-micro aggregate ceilings, separately enforced per-task allocations, conservative failed-attempt debits, and no spending authority from a synthetic price or prepaid-plan assumption. The provisional caller-sampled boot clock is not independent time authority. No provider, UI, host, process, production-key or scored action follows from this plan.

## Review focus

1. Stop commits in the resource store while a state `started` append or UI claim races: the prior durable stop intent must deny that grant, including after coordinator crash (Tasks 1–3).
2. A lost acknowledgement after a signed append or mailbox claim must leave one pending identity, not mint another event, command or lease (Tasks 1–4).
3. A writer that bypasses the coordinator, or a replaced lock/journal/store path, must fail closed for schema two while historical schema one still works (Tasks 1–2).
4. A stop arriving after grant activation must retain the owned effect as in-flight; an unfinished grant must not become Invoke permission (Tasks 3–5).
5. A delayed, cross-boot, replayed or changed-command lease must fail at the workstation before the actual Invoke, including after readiness wait or restart (Tasks 4–5).

### Task 1: Inert protected guard and durable intent journal

**Files:** Create `examples/cybergym/nooa_cybergym/leaderboard/subset_effect_coordinator.py` and `examples/cybergym/tests/leaderboard/test_subset_effect_coordinator.py`. No existing effect caller changes in this task.

**Interface:** `CoordinatorBinding` contains exact run, epoch, admission/budget digests, held state-root identity, held resource-store identity, held **preinitialized** mailbox database and marker identities, mailbox-binding digest, and independently checked service/signer custody. `OperationBinding` contains one target store, preparation/attempt where applicable, its expected verified **pre-write** revision/content digest and an independently predeclared exact **post-write** outcome identity or operation-specific transition verifier. A merely changed digest is never sufficient to settle an intent; if a writer cannot supply an exact postcondition before mutation and verify it afterward, that writer remains blocked. A separate `CompositeStopBinding` fixes the exact resource, signed-state and mailbox sub-operations, store identities, expected pre/post outcomes and order before the first write. `SubsetEffectCoordinator.create_v2(root: Path, *, binding: CoordinatorBinding, backend: CoordinatorBackend)` binds these independently obtained identities to one create-once protected root. `guarded_intent(*, operation_id: str, kind: str, exact_binding: OperationBinding | CompositeStopBinding)` yields one live, non-reusable `CoordinatorIntent` while holding the cross-process guard, commits and reads back one canonical pending intent before the caller may mutate any target store, then records exact per-store sub-intent and readback outcomes. The Task 1 kinds distinguish state append, resource debit/clock/stop/closure, mailbox publish/claim/ack/fence and composite stop; mailbox initialization is rejected in Task 1. Read-only reconciliation is deferred to Task 3. Reopening a pending or inconsistent intent returns `BLOCKED`, never a permit; a partial composite stop retains its denial latch. The journal is local denial state, not signed campaign evidence.
