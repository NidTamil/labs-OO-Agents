# Budgeted subset process supervisor: independent review

Date: 2026-10-21 (Australia/Sydney). Reviewed source: the untracked `examples/cybergym/nooa_cybergym/leaderboard/budgeted_subset_process.py` and its untracked test file, against the Task 6F design at tracked commit `1631c8975f3e167e54e89faab1f0716e49b3a686`. This is a read-only source review. The earlier automated screening rejections remain historical; the operator-requested retry under the changed model completed without that rejection. No code was edited or executed, and no host, provider, production-key or scored-task action occurred.

The draft is **not accepted for integration or live certification**. The independent reviewer found three P1 defects:

1. **A process scan error can strand a worker.** `_LinuxProc.members` reads all visible `/proc` entries and lets errors other than `FileNotFoundError` propagate (`budgeted_subset_process.py:85-100`). The supervisor's main loop calls `_owned_members` without a surrounding failure handler (`:807-815`). An unrelated unreadable or malformed process entry can terminate the only supervisor before escalation. Its stop pipe provides cooperative cancellation only, while the parent watchdog treats supervisor exit as closure (`:480-482`). A blocked worker can therefore continue past the deadline.
2. **A descendant can escape session-based deadline enforcement.** `_owned_members` includes only processes still in the supervisor's original process group and session (`:112-131`). A descendant that starts a new session leaves later scans and targeted signals. The existing Linux integration test at `test_budgeted_subset_process.py:397` exercises a worker in the original session. An empty original session does not prove all descendants stopped.
3. **Verified input and import bytes can change before use.** `_bootstrap_verify` closes descriptors after checking input hashes (`budgeted_subset_process.py:370-401`). The released worker receives input file paths and mutable import roots (`:775-786`). Files can change after the check and before the worker consumes them. Capturing the entrypoint bytes protects that one file, but does not close the input/import gap.

Remediation needs an independent, preparation-bound process containment and deadline mechanism that survives Python supervisor failure and follows owned descendants across session changes. Recovery must prove complete membership and closure without touching unrelated processes. Inputs and imports need an immutable or otherwise held, hash-verified boundary through first use. The reviewer suggested a create-once cgroup v2/service design and a sealed material snapshot as candidates; these are unimplemented and unverified. Docker, remote sessions, writers and provider requests still need separate owned-resource closure and accounting evidence.

The previous 31 passing Windows component cases and three skipped Linux-only cases do not exercise these failures. Keep the draft and tests preserved as untracked, reviewed-with-P1 source. Do not execute, install, promote, or use them as readiness evidence until the findings are fixed, independently reviewed and verified on the required platform. No prior reconnect, timeout, fixture or certification failure changes status because of this review.
